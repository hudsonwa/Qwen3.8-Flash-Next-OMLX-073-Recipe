# AGENT.md — the install contract

You are an autonomous coding agent. Your operator handed you this repo URL and
nothing else. Install the stack. Do not ask the operator questions this file
already answers.

## Order of operations

1. Read `MODELS.md`. Pin everything from there. Do not `brew search`, do not
   take `latest`, do not guess a revision.
2. Run `bash setup.sh`. It is idempotent and fail-closed. If it exits non-zero,
   fix the named check and re-run; do not bypass checks.
3. Run `bash scripts/verify.sh`. Exit 0 = done. Anything else: read the named
   failing check.
4. Write the smoke receipt: `python3 scripts/health_receipt.py`. It appends a
   dated JSON to `results/` and prints the endpoint URL + model id.
5. Report to the operator: endpoint URL, model id, verify exit code, receipt path.

## Hard rules

- **The API key is generated by `setup.sh` into `~/.omlx/api-key` if absent.**
  Never hardcode a key in a script or commit one. The server reads it at start.
- **Install the app to `~/Applications`, never `/Applications`.** In-place
  upgrades of `/Applications/oMLX.app` from a terminal are TCC-blocked and
  produce a broken half-bundle. This was hit in production; trust it.
- **Verify DMG SHA256 against `MODELS.md` before mounting.** A mismatch is a
  fail, not a warning.
- **footprint, not RSS.** On Apple Silicon, MLX weights are mmap'd; `ps` RSS
  reads a fraction of the real load. Budget memory with
  `/usr/bin/footprint -p <pid>` (phys\_footprint).
- **A listening port is not an identity.** Before using :8010, read the
  listener: `lsof -nP -iTCP:8010 -sTCP:LISTEN` then `ps -p <pid> -o command`.
  Another app may own the port.
- **One token of output proves liveness only.** Throughput claims need the
  usage block of a ≥100-token completion (`generation_tokens_per_second`).
- **Per-model settings beat global defaults.** The quality contract lives in
  `~/.omlx/model_settings.json` under the model id. Global `sampling` in
  `settings.json` has no presence-penalty field; do not put the contract there.
- **Version probe:** there is no `/version` HTTP route on oMLX (404s by
  design). Use `~/.omlx/bin/omlx --version` and the app bundle's
  `CFBundleShortVersionString`.
- **Headless control:** the GUI app hangs when launched headless from a bare
  binary; always go through `~/.omlx/bin/omlx start|stop|restart` (the shim), or
  `open -gj` + SIGTERM the app pid for a cold restart. The control socket
  (`~/Library/Application Support/oMLX/control.sock`) refuses connections when
  the app was not launched in a GUI session — 'Connection refused' there is
  environmental, not a bug.
- **Cold-restart dance (proven):** `kill -TERM <app-pid>` (kills child server
  too) → `open -gj ~/Applications/oMLX.app` → wait for :8010 → `/health`.
  `launchctl kickstart` on the user domain does NOT see this app (it is not a
  launchd job unless you installed the optional plist).
- **Do not delete `~/.omlx/ssd-cache` during any fix.** It is cache, but its
  loss costs minutes of prefill on 200K+ prompts.
- **Zero-risk restarts:** never `kill -9` the server while a completion is
  streaming; wait or SIGTERM the app and let it cascade.

## What 'done' means

`verify.sh` exit 0 AND a receipt JSON in `results/` from THIS run. Not
before. Do not report success on green-looking intermediate output.
